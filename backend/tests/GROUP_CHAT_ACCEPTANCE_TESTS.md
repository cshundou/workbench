## 四、核心工作流

| 编号 | 验收项 | 操作步骤 | 预期结果 | 优先级 |
|------|--------|----------|----------|--------|
| GC-FLOW-01 | 标准流程 | 提交「分析 Q2 销售数据并生成报告」 | PM 拆解 → 各 Agent 执行 → 提交审核 → 审核通过 → 最终交付 | P0 |
| GC-FLOW-02 | 结果交接 | 观察消息流 | 每个 Agent 完成后在群内发送 result_delivery 并通知 PM | P0 |
| GC-FLOW-03 | 用户发言 | 任务执行中在底部输入框发言 | 用户消息出现在聊天流，持久化到数据库 | P1 |
| GC-FLOW-04 | 断线重连 | 刷新页面或重连 WebSocket | 通过 GET /sessions/{id} 恢复历史消息 | P1 |

## 五、强制审核环节

| 编号 | 验收项 | 操作步骤 | 预期结果 | 优先级 |
|------|--------|----------|----------|--------|
| GC-REV-01 | 四维度审核 | 观察审核员发言 | 审核涵盖完整性、准确性、逻辑性、合规性 | P0 |
| GC-REV-02 | 审核通过 | 正常完成任务 | 审核员发送 ✅ 通过，PM 发送最终交付物 | P0 |
| GC-REV-03 | 审核打回 | 模拟/触发审核不通过 | 审核员指出问题，任务打回对应 Agent 修改 | P0 |
| GC-REV-04 | 三次打回上限 | 连续 3 次审核不通过 | 状态变为 human_review，提示转人工审核 | P0 |
| GC-REV-05 | 审核计数 | 检查 session.review_count | 每次打回 review_count 递增，最多 3 次 | P1 |
